Статус: этап 1. Список ограничивает реализацию: пункт, помеченный как открытый, нельзя закрыть правдоподобным значением в коде.

## 1. Технические риски

| ID | Риск | Следствие | Что уже сделано в проекте |
| --- | --- | --- | --- |
| R1 | Протокол и прошивка АСКА-02 неизвестны | Неверный кадр может пустить газ или испортить режим колонки | Драйвер до акта только отказывает; «Искра 1.72» не используется |
| R2 | Неизвестно число каналов и тип линии | Опрос чужого адреса заденет другое устройство | `max_channels` заполняется по факту; сверх факта канал не опрашивается |
| R3 | Одновременный отпуск при общем адаптере | Наложение команд на одном интерфейсе | Один секвенсор, одна активная транзакция обмена |
| R4 | Обрыв ответа после команды пуска | Повтор создаст вторую дозу | `UNKNOWN` запрещает повтор, пока чтение не снимет неизвестность |
| R5 | Пропадание питания во время отпуска | Потеря факта или повторный пуск после включения | Намерение пишется до команды; старт не воспроизводится слепо; факт берётся из дельты счётчика |
| R6 | Счётчик недоступен или сдвинулся назад | Неверная сумма покупателю | Сумма не считается, продажа остаётся в `NOT_READY` |
| R7 | Kaspi не поддерживает запрос статуса или ключ идемпотентности | Нельзя отличить списание от сбоя | Вторая попытка при `UNKNOWN` запрещена |
| R8 | Схема чека предоплаты выбрана наугад | Неверный налоговый документ | Встроенное правило `DENY_ALL`; произвольный чек из JSON не собирается |
| R9 | Webkassa недоступна | Зависшая предоплата | Шлюз закрыт, если политике нужен чек до отпуска; неизвестная сдача только сверяется |
| R10 | Центр недоступен | Потеря учёта сети | Продажа полная в SQLite; outbox догоняет без дубля |
| R11 | Порча или потеря диска кассы до синхронизации | Потеря смены | Ежедневная копия SQLite с этапа продаж; до синхронизации это всё ещё риск одного объекта |
| R12 | Секрет Kaspi или Webkassa на компьютере кассира | Кража при доступе к системе | Ключница Windows, секрет не в SQLite и не в репозитории; шифрование диска в подготовке к эксплуатации |
| R13 | Кража токена станции | Подделка потока учёта | Хранится хеш, токен отзывается; токен не даёт команд колонке |
| R14 | Учётная запись офиса скомпрометирована | Попытка удалённо управлять газом | Такого API нет; коммерческая блокировка только запрещает новые продажи |
| R15 | Расхождение предоплаты и факта | Долг покупателю или спор | Дельта фиксируется; автоматический возврат не запускается |
| R16 | Факт больше предоплаты | Лишний газ | Инцидент и останов новых продаж этой колонки; доплата сама не берётся |
| R17 | Сдвиг часов | Путаница смены и фискального времени | Порядок событий — последовательность станции; время фискализации остаётся открытым вопросом |
| R18 | Две копии бизнес-правил | Разная сумма на кассе и в отчёте | Расчёт на кассе, центр хранит принятую копию |
| R19 | Учебный успех оплаты попал в боевой профиль | Отпуск без денег | Сборка `production` не содержит тестовый порт; это проверяет тест |
| R20 | Эмулятор случайно открыл реальный порт | Команда на живую колонку | У эмулятора нет параметров порта; профиль `production` его не создаёт |
| R21 | Нагрузка 1000 станций | Очередь пульса и отчётов | Пачки, случайный сдвиг пульса, индексы по организации; реплика — только после замера |
| R22 | Целостность журнала | Тихая правка файла базы | Цепочка хешей обнаруживает разрыв; от подмены файла целиком защищает копия на центре |
| R23 | Повторная доставка пачки с другим телом | Подмена продажи | Тот же `event_id` и другой хеш отвергаются |
| R24 | Закрытие смены с незавершённым газом | Деньги и газ в разных сменах | Закрытие смены в этом состоянии запрещено |

Вероятность и тяжесть пересматриваются после обследования АСКА-02 и ответов Kaspi и Webkassa. До этого R1, R7 и R8 считаются блокирующими для боевого пуска, но не для разработки эмулятора.

## 3. Как закрывать вопрос

1. Ответ записывается: кто подтвердил, дата, ссылка на документ поставщика или письмо бухгалтера.
2. Если ответ меняет границу модуля, сначала добавляется строка в журнал решений архитектуры.
3. Для фискализации ответом является именованное правило и тесты на него. Свободный набор полей чека ответом не считается.
4. Для АСКА-02 ответом является акт обследования. Строка протокола в конфигурации без акта не заполняется.
5. Пока записи нет, реализация остаётся на закрытом шлюзе из проекта: отказ обмена, `DENY_ALL`, запрет второй попытки, отсутствие команды с центра.

## 4. Что не является риском реализации этапа 1

На этапе проектирования сознательно нет кода, миграций и стенда. Это не отставание по этапу 2: этап 2 ждёт подтверждения документов. Подключение настоящего оборудования до закрытия Q1–Q6 противоречит этому проекту.
