# Сопровождение центра и кассы

Секреты задаются переменными окружения на сервере и не коммитятся. В репозитории нет пароля, токена устройства и адреса боевого сервера.

## Центр

```bash
POSTGRES_USER=agzs POSTGRES_PASSWORD=... POSTGRES_DB=agzs \
CENTRAL_BOOTSTRAP_USER=platform CENTRAL_BOOTSTRAP_PASSWORD=... \
docker compose up --build
```

PostgreSQL наружу не публикуется. Nginx принимает 80 и 443 и перенаправляет HTTP на HTTPS. Сертификат кладётся в `deploy/nginx/certs/` локально, каталог в git не хранит ключи.

Прикладная роль видит коммерческие строки своей организации. В PostgreSQL для этих таблиц включается и принудительно применяется row-level security: без `agzs.organization_id` или признака платформы строки не видны. Запрос API без заголовка организации коммерческие данные не возвращает.

Маршрутов пуска, останова и дозирования нет. Центр может запретить новые продажи флагом `sales_blocked`. Этот флаг не закрывает клапан.

Касса без `AGZS_CENTRAL_BASE_URL` продаёт локально и копит outbox. Повторная пачка с тем же телом получает `DUPLICATE`. Другое тело при том же `event_id` отклоняется.

Миграции центра запускаются из каталога `central-server`: `alembic upgrade head`. В контейнере это делает команда запуска.

## Копии

Касса: сценарий резервного копирования вызывает API SQLite и пишет файл в `{AGZS_DATA_DIR}/backups/`.

Центр:

```bash
DATABASE_URL=postgresql://... BACKUP_DIR=/var/backups/agzs deploy/backup/pg-dump.sh
pg_restore --clean --if-exists -d "$DATABASE_URL" /var/backups/agzs/agzs-ГГГГММДД.dump
```

Учебное восстановление выполняется до боевых продаж: поднять пустой экземпляр, восстановить дамп, проверить, что продажа читается пользователем своей организации и не читается чужой.

Приём 1000 пульсов подряд не создаёт продаж. Это проверка пути записи, а не замер сети из тысячи станций. Перед эксплуатацией тот же сценарий гоняется на стенде с реальным PostgreSQL.

## Касса на Windows

1. Установить Python 3.12.
2. Создать виртуальное окружение и поставить зависимости из `requirements-dev.txt` и `agzs-station[ui]`.
3. Для учёбы: `AGZS_ENV=emulator` и `AGZS_PUMP_DRIVER=emulator`.
4. Для промышленного профиля драйвер только `aska02`. Пока нет акта допуска, обмен отклоняется.
5. Секреты промышленного профиля рассчитаны на Диспетчер учётных данных Windows, имя службы — `AGZS_KEYRING_SERVICE_NAME`.
6. Обновление схемы — только `alembic upgrade`, без ручной правки файла базы.
